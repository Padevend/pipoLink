# Provider Cloudflare R2

R2 est le provider recommandé pour des assets privés et partagés. Le bucket peut rester privé : le backend lit et sert les objets après ses propres contrôles d'accès. Il n'est donc pas nécessaire de configurer un domaine public ou `R2_PUBLIC_URL`.

```dotenv
STORAGE_SDK_DRIVER=r2
R2_ACCOUNT_ID=<account-id>
R2_ACCESS_KEY_ID=<access-key-id>
R2_SECRET_ACCESS_KEY=<secret-access-key>
R2_BUCKET_NAME=pipolink-production
# R2_PUBLIC_URL= facultatif, seulement pour reconnaître d'anciennes URLs
```

1. Créez un bucket dans [Cloudflare R2](https://dash.cloudflare.com/?to=/:account/r2).
2. Dans **R2 > Manage API Tokens**, créez un token **Object Read & Write** limité à ce bucket.
3. Copiez immédiatement l'Access Key ID et le Secret Access Key : le secret ne peut pas être relu.
4. Placez les quatre variables dans `APPLICATION_ENV_JSON`, puis exécutez le workflow **Synchronise le secret d'environnement AWS**.

Cloudflare documente la création du bucket et des clés S3, y compris l'endpoint `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`, dans son [guide S3 R2](https://developers.cloudflare.com/r2/get-started/s3/). Limiter le token à un seul bucket réduit fortement la portée d'une compromission.

Le driver utilise `region: auto` et l'API S3 compatible. Ne rendez pas le bucket public : les routes de PipoLink fournissent l'autorisation applicative.
